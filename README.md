## 🧭 指令词（Command Words）——决定你的答案长什么样

> ⚠️ **这是最容易拿分也最容易丢分的地方。** 题目用什么动词，答案的"形状"就完全不同。

| 指令词 | 中文 | 你要写什么 | 典型分值 |
|--------|------|-----------|---------|
| **State / Give / Identify** | 说出 / 给出 / 指出 | **只要术语或事实**，一句话，不解释 | 1 |
| **Name** | 命名 | **只要名字** | 1 |
| **Describe** | 描述 | **说清楚是什么 / 会发生什么** —— 要用完整的句子，点出特征 | 2–4 |
| **Explain** | 解释 | **Describe + why** —— 必须有因果（"because"、"this means that"、"so that"） | 2–6 |
| **Discuss** | 讨论 | **正反两面**，每个点都要展开 | 4–8 |
| **Compare** | 比较 | **相似点 + 差异点都写**，差异要成对 | 2–6 |
| **Tick / Circle** | 打勾 / 圈出 | 只标记，**不要多写** | 1–3 |
| **Draw and annotate** | 画图并标注 | **每一段标注都是得分点**，画完一定要写英文标签 | 4–6 |
| **Complete the table** | 完成表格 | 按行给分，**拼写必须能辨认** | 4–6 |

### ⚠️ 最关键的区分：Describe vs Explain
> **Describe** = what happens（发生了什么）
> **Explain** = why it happens / how it works（为什么 / 怎么做到的）
>
> 例：题目问 *Explain how the firewall protects the network*
> ❌ "It blocks hackers."（这是 describe，而且是 **TV**）
> ✅ "It **examines incoming traffic** and **checks it against set criteria** such as a blacklist；if the traffic **does not meet the criteria it is rejected**, so unauthorised data cannot enter the network."

## 🔍 Mark Scheme 黑话表（看懂评分标准就能多拿分）

> 官方 Mark Scheme 里出现这些缩写，**理解它们能帮你判断自己的答案能不能得分**。

| 缩写 | 全称 | 意思 |
|------|------|------|
| **TV** | Too Vague | **太笼统，不给分**。例："different access levels"、"best path"、"two different keys are used" |
| **NE** | Not the Error / No Evidence | **没有答到问题**。例：题目问 register，你答 "register alone" |
| **NAQ** | Not Answering the Question | **答非所问**。例：题目问 "purpose of the optical mouse"，你答 "it is an input device" |
| **BOD** | Benefit of the Doubt | **存疑但给分**。例：把 "clock cycles" 写成 "clock ticks/pulses" |
| **Mark the first answer given** | — | **只改第一个答案**，多写的作废 |
| **Mark whole answer** | — | **整体判分** —— 必须写成配对（HLL vs LLL 题就是这种） |
| **"Any N from"** | — | 给分点比总分多，**任选 N 个**即可 |
| **"MAX N if no expansion"** | — | **不展开最多给 N 分** —— 这是"必须解释"的信号 |
| **"Do not accept…"** | — | 明确排除项，**写了也不算分** |

### ⚖️ 三条铁律

**① 品牌名不得分**
> 试卷封面就印着：**"No marks will be awarded for using brand names of software packages or hardware."**
> ❌ "Google Chrome"、"Microsoft Word"、"Apple Siri"
> ✅ "web browser"、"word processor"、"smart home device"

**② Repeat 的答案不得分**
> 题目已经给你的词，**再写出来不算分**。
> 例：题目说 "The computer has primary storage. One example of primary storage is **cache**. Give one **other** example." → 写 "cache" 或已经在题干里的 "RAM" = **0 分**。

**③ 不结合题干情境的通用答案不得分**
> 这是 **Unit 6 考官报告的头号抱怨**，也适用于全卷：
> "Candidates gave **generic answers that were not applied to the context** given in the question."
> ✅ **把题干里的数字、传感器名、设备名抄进你的答案。**

## ⚡ 全卷通用失分点 Top 12

| # | 失分点 | 正确做法 |
|---|--------|---------|
| 1 | **不看指令词** —— Explain 题只写 Describe 的内容 | 看到 **Explain** 就必须出现 **because / this means / so that** |
| 2 | **不结合题干情境** | 抄题干的名词和数字进答案 |
| 3 | **只写点不解释** | Discuss/Explain 题每个点后面必须接一句"所以…" |
| 4 | **单位搞错（1024 vs 1000）** | 存储单位用 **1024**；网络速率（bit rate）可用 1000 |
| 5 | **方向搞反** | 证书 **server→browser**；请求 **browser→web server**；地址 **PC→MAR**（不是 MDR） |
| 6 | **把 actuator 当成能显示屏幕内容** | Actuator 只引起**物理运动**（motor / valve / brake / piston） |
| 7 | **把 ALU 当成 register** | 组件 ≠ 寄存器。寄存器只有 **PC / MAR / MDR / CIR / ACC** |
| 8 | **把 HDD 当成 optical storage** | **HDD = magnetic**（虽然有旋转盘片） |
| 9 | **性能题不说"增加还是减少"** | 必须写 "**if the clock speed is INCREASED**"，不能只说 "clock speed affects performance" |
| 10 | **写"encryption 能阻止黑客"** | Encryption **不能阻止入侵**；数据仍被窃取，只是**无法被读懂** |
| 11 | **Compare 题只写一边** | A 怎样 + **whereas** + B 怎样，**两边都要写** |
| 12 | **答案里出现品牌名** | 用通用词（"web browser" 而不是 "Chrome"） |
| 13 | **二进制加法用"转十进制加完再转回来"** | 必须写**二进制竖式 + 进位**；**"show all working" 本身就是得分点**（2023–2025 八份考官报告点名） |
| 14 | **二补码在正数最前面加个 1** | 必须 **flip and add 1（取反加一）**；最高位权重是 **−128** 不是 +128 |
| 15 | **写 "cable" / "path" / "best path"** | 用 **wire**；路由器题必须写 "the **router determines/assigns** the route" |
| 16 | **压缩题写文件格式（JPEG / MP4 / ZIP）** | 方法只有 **lossy** 和 **lossless** 两类，2026 判分明确禁止 |
| 17 | **"fast" / "better" / "less space" 没有比较对象** | **"Fast/faster alone is NE"** —— 必须写出跟什么比、用来做什么 |
| 18 | **混淆 check digit 和 checksum** | **check digit = 数据输入**（防人为输错）；**parity / checksum / echo / ARQ = 数据传输** |

## 🎯 投入产出比：什么该背，什么可以放

### ⛔ 整份题库（2020–2026）**从未考过**的

| 内容 | 说明 |
|---|---|
| **RLE 单独出题** | **从未**作为独立题目出现。它只是**无损压缩的举例**（判分里写 "e.g. RLE"）。**不要去练 RLE 编码/解码**，只要会写：「无损压缩的一个例子是 RLE，它把重复数据**识别、分组并记录重复次数**」 |
| **ISBN-10 / ISBN-13 算法** | **从未**出现。校验位题都是**条形码**（barcode）或通用描述，考的是「算出来 → 附在末尾 → 扫描时重算 → 比对」这个流程，**不是加权算法** |
| **触摸屏类型 / 打印机 / 投影仪 / 2D–3D 扫描仪 / QR 码** | 2022 年后**从未考过**（Unit 3），别在这里花时间 |
| **键盘等输入输出设备如何工作** | **已从考纲删除** —— 写了**直接 0 分**（2025 Nov 考官报告原话） |

### ✅ 性价比最高的（几乎每场必考）

1. **Unit 1**：进制转换 · 二进制加法 + overflow · 二补码 · 有损/无损压缩
2. **Unit 1**：存储单位换算（一律 **1024**）—— 常作**卷首 1 分题**，等于白送
3. **Unit 2**：串行/并行 + 单工/半双工/全双工 —— **得分结构 = 特征（1 分）+ 展开后果（1 分）**
4. **Unit 2**：查错方法（parity / checksum / echo check / ARQ）
5. **Unit 2**：加密的**术语定义**（encryption key / cipher text / symmetric / asymmetric）—— 2026 比重明显上升
6. **Unit 3**：寄存器 · FDE 周期 · cores–cache–clock 性能对比
7. **Unit 6**：sensor → microprocessor → actuator 五步链

### 📈 2026 的新趋势：**题目变碎了**

> 从「Describe X **[4]**」变成**一连串 1 分小题**：
> - June 2026 **P11 Q3** = **五个独立**的 1 分进制换算
> - June 2026 **P12 Q1(c)** = **三个独立**的 1 分题（数制判断 + 两个二补码）
> - June 2026 **P12 Q4(c)** = **三个独立**的 1 分加密题（方法名 / 密钥 / 密文）
>
> → **定义和单步运算的性价比上升**；每个术语的**精确措辞**比长篇大论更重要。
> → 复习时把每个核心术语当成「**1 分题**」来准备：一句话，措辞标准，不多写。

> 重点补 **Unit 3**（分值最高）和 **Unit 6**（模板最固定）

### 考前一晚 / 当天早上
> 只看这三样：
> 1. 本页的 **指令词表** 和 **Mark Scheme 黑话表**
> 2. Unit 3 的 **🧠 一页纸速记**（分值最高）
> 3. Unit 6 的 **sensor → microprocessor → actuator 五步模板**

### 考试中
> - **先读指令词**，再读题目内容
> - **算分**：题目给几分就写几个点（3 分题写 3 个独立点，宁多勿少）
> - **画图题**：每一段都标英文，标签就是分
> - **不确定拼写时**：写清楚能辨认即可，拼写错误通常不扣分（但 `user account management` 这类标准术语必须对）
> - **不要空题**：写对方向的一部分也比留白强
